# 执行计划：模块拆分与告警系统

更新时间：2026-05-04

## 总方向

系统继续朝三个市场模块推进：

- 币安合约：成交量前 50，主网 API 为核心；表格轻量计算 MA60 偏离，图表交给 TradingView。
- 国内期货：独立 UI、独立数据源、独立符号映射。
- 外盘期货：独立 UI、独立数据源、独立符号映射。

底层统一通过 `EventBus` 发布标准 tick，UI 和 AlertEngine 都只消费标准契约。

## 已完成

- 币安模块接入真实 API Client。
- 币安只为表格指标拉最近 60 根 close 并保存 `sum59` 数字快照，不做本地图表缓存。
- 币安监控目标为成交量 Top 50。
- 新增 `TradingViewSymbolMapper`。
- 新增国内期货 Sina 数据层验证脚本。
- 新增外盘期货 Yahoo 数据层验证脚本。
- 新增 `MarketDataQuality`。
- 新增 `AlertEngine` 和 SSE `alert` 推送。
- 全局设置接入 `/api/settings` 读写。
- 全局设置显示并可保存所有外部 API 端点。
- 全局预警支持按资产类别分别设置瞬时涨跌阈值：虚拟货币、期货、其它。
- 预警通知文案改为中文。

## 当前阶段：配置与预警解耦

目标：让预警设置不再是单一统一设置，而是按资产类别细分。

实现规则：

- 虚拟货币对应 `Crypto_Binance`。
- 期货对应 `Futures_CN` 和 `Futures_Global`。
- 其它对应 `Stocks_CN` 和 `Macro_Home`。
- 全局分类预警只配置 `instant_move_percent` 和 `instant_window_seconds`。
- 示例：虚拟货币 30 秒涨跌 5%，期货 60 秒涨跌 1%。
- 底层阈值仍放在 `AlertSettings.thresholds`，不引入单品种覆盖表。

## 下一步开发顺序

1. 完成全局设置页细化
   - 把 API 设置、分类预警、通知设置拆成清晰区域。
   - 保存时调用 `/api/settings`。
   - 后续增加“恢复默认”和“测试接口”按钮。

2. 国内期货模块 UI
   - 独立页面，不复用币安表格逻辑。
   - 接入国内期货列表、交易所、合约月份、主力合约标识。
   - 接入 Sina 数据层，输出标准 tick。
   - 先做低频刷新，不做重后台 K 线缓存。

3. 外盘期货模块 UI
   - 独立页面，不复用国内期货逻辑。
   - 接入 Yahoo 数据层和 TradingView mapper。
   - 对空数据、休市、延迟数据明确标注。

4. 通知通道
   - 前端预警面板继续保留。
   - 桌面通知和声音提醒先在前端实现。
   - Telegram/企业微信/飞书等机器人通知必须放后端，token 不进前端 bundle。

5. Google Cloud 准备
   - Dockerfile。
   - Cloud Run 环境变量和 Secret Manager。
   - 健康检查 `/api/health`。
   - 日志和异常重启策略。

## 轻量化约束

所有后续开发必须遵守：

- 不用一个大轮询引擎混跑所有市场。
- 不把国内期货、外盘期货、币安合约写进同一套品种逻辑。
- 不为图表长期维护后台 K 线缓存。
- 计算指标时优先保存聚合结果，而不是保存完整历史。
- 数据源失败时保留旧值并标记数据质量，不让单个品种拖垮模块。

## 风险清单

- Binance Global Futures 对出口地区敏感，本地代理或 Google Cloud 区域需要实测。
- testnet 数据只能用于链路演示，不能用于真实偏离值判断。
- Sina 分钟线可能返回旧合约或休市数据，需要数据质量标记。
- Yahoo 1m 数据在休市、限流或地区网络不稳定时可能为空。
- API 设置保存后，已有 WebSocket 连接需要重启模块才能完全切换。
