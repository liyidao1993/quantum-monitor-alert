# 架构审查 2026-05-04

## 结论

当前项目的底层市场模块已经按市场目录拆开，UI 与底层主要通过标准数据契约、HTTP API、SSE 和 EventBus 连接。今天已补上通用 `MarketDataUpdated` 事件，后续国内期货、外盘期货接入时，不需要再让 AlertEngine 或 SSE 绑定某个具体市场事件。

## 已确认满足

- `Crypto_Binance`、`Stocks_US`、`Futures_CN`、`Futures_Global` 的数据源代码位于各自模块目录。
- 统一符号映射来源为 `4_Shared_Types/symbol_mapping/TradingViewSymbolMapper.ts`。
- 旧前端映射文件 `src/shared/markets.ts` 已删除，避免两套映射长期分叉。
- 全局分类预警只配置瞬时涨跌阈值：
  - 虚拟货币：30 秒涨跌 5%
  - 期货：60 秒涨跌 1%
  - 其它：独立保留
- `AlertEngine` 订阅通用 `MarketDataUpdated`，不再只订阅 Binance。
- SSE tick 快照使用 `market:symbol` 作为 key，避免不同市场同名品种互相覆盖。
- `/api/settings` 已增加轻量请求体验证。
- `ConfigManager.save` 已改成串行原子写，降低配置文件损坏和并发覆盖风险。
- `Futures_Global` 已新增独立前端视图 `src/views/FuturesGlobalView.tsx`，UI 只调用 `/api/futures-global/klines`，不直接依赖 Yahoo 原始 API。
- `/api/futures-global/klines` 由后端封装 Yahoo Chart、符号映射和数据质量检查，已验证 `GC1!`、`NQ1!` 返回 `ok`。
- `Futures_CN` 已拆到独立前端视图 `src/views/FuturesCnView.tsx`，UI 只调用 `/api/futures-cn/klines`，不直接依赖 Sina 原始 API。
- `Futures_CN` 后端已同时封装新浪分钟线和 `nf_` quote 行情，中文 GB18030 解码已处理；休市日最近交易日数据不再误判为接口失败。
- `Stocks_US` 已新增独立前端视图 `src/views/StocksUsView.tsx`，UI 只调用 `/api/stocks-us/klines`，不直接依赖 Yahoo 原始 API。
- `/api/stocks-us/klines` 由后端封装 Yahoo Chart、符号映射和数据质量检查，已验证 `AAPL`、`MSFT`、`NVDA`、`TSLA`、`SPY` 返回 `ok`。
- `Crypto_Binance` 列表视图已拆到 `src/views/BinanceView.tsx`，`src/App.tsx` 只保留查询、排序状态和模块编排。
- 按需图表窗口已拆到 `src/components/ChartWindow.tsx`，`src/App.tsx` 不再直接依赖 `lightweight-charts` 或底层符号映射。
- 全局设置页已拆到 `src/views/SettingsView.tsx`，分类预警编辑和 API 字段编辑逻辑不再放在应用壳里。
- 宏观首页已拆到 `src/views/MacroHomeView.tsx`，`src/App.tsx` 进一步收敛为导航、状态编排、模块路由和告警浮层。
- 全局设置已新增 `GET /api/settings/test-endpoints` 连通性测试，UI 可直接显示 Binance、Sina、Yahoo、TradingView 的当前状态。

- B1：SSE 重连定时器累积，已修复。
- B3：ChartWindow fetch 未取消和依赖缺失，已加入 `AbortController` 和 `item.market` 依赖。
- B4/Q13：AlertEngine 只订阅 Binance，已改为通用 `MarketDataUpdated`。

- B6：settings POST 无校验，已增加轻量校验。
- B8：SSE `module_statuses` 只含 Binance，已改为读取 LifecycleController 全部状态。
- Q11：AlertEngine 启动异常静默，已改为显式日志。

## 仍需后续处理

- `src/App.tsx` 已从单体视图文件收敛为应用壳；后续可继续拆出 `AlertDock`、导航栏和顶部工具条，但这已经不是市场模块隔离的阻塞项。
- 国内期货已新增 `FuturesCnMonitorModule`，可启动/停止实时轮询并发布标准 tick；停止模块后不再后台运行。
- 顶部启停按钮已改为按当前模块控制，停止模块时会清理对应 tick 快照，避免不同模块互相影响。
- 国内期货轮询已补充 stop 后二次状态检查，避免请求刚返回时继续发布暂停后的残留 tick。
- 外盘期货目前同样是按需 HTTP 读取，不是常驻 EventBus 模块。这符合当前轻量阶段；如果以后要实时预警，再单独增加 `FuturesGlobalMonitorModule`，不要和国内期货或币安模块混写。
- 美股目前是按需 HTTP 读取，不是常驻 EventBus 模块。这符合当前轻量阶段；如果以后要实时预警，再单独增加 `StocksUsMonitorModule`，不要和期货或币安模块混写。
- Telegram、桌面通知、声音提醒目前仍主要是配置入口，通知通道需要下一阶段实现。
- Binance 代理 HTTP 响应构造仍是手写路径，后续应替换为更可靠的 fetch dispatcher/ProxyAgent 方案。
- Google Cloud 部署前需要补 Dockerfile、Secret/env 管理、健康检查和退出清理验证。

## 下一步建议

下一步优先处理币安出口恢复后的端到端复测，重点是 Top50、WebSocket、轻量 MA60 偏离、TradingView 按需图表和瞬时预警链路。UI 拆分和接口测试能力已经达到当前阶段的核心目标。
