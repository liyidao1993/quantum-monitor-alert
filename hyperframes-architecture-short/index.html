ARCHITECTURE IN 12 SECONDS

不同架构，
其实是在选择
变化怎么发生

不是越新越好，而是看团队、业务、复杂度。

单体 分层 微服务 事件驱动
01 / MONOLITH + LAYERS

单体和分层：
先把路修直

界面层 UI
业务层 Service
数据层 Repository
数据库 Database

适合早期产品：部署简单，调用清楚，改动集中。

02 / MICROSERVICES

微服务：
把变化拆给不同小队

用户服务
订单服务
支付服务
库存服务

适合复杂业务：独立发布，但网络、监控、数据一致性会变难。

03 / EVENT-DRIVEN

事件驱动：
让系统听见“发生了什么”

适合削峰、解耦、异步协作，但排查链路要更认真。

订单已创建
→
支付 / 库存 / 通知
各自响应
Event Bus
小项目单体 + 分层，跑得最快。
大组织微服务，边界更清楚。
高并发事件驱动，削峰解耦。
记住一句：架构不是图好看，是让下一次变化更便宜。
